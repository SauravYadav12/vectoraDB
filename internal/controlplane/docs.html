VectoraDB

A serverless PostgreSQL platform: instant copy-on-write branches, time-travel, a database per AI agent, and high availability — with native transaction speed.

Overview

VectoraDB runs stock PostgreSQL on local storage for native commit/read latency, and moves durability, branching and time-travel off the hot path: ZFS copy-on-write clones for instant branches and async WAL archival to object storage. You drive it with one CLI (vectoradb) and reach it through a single proxy endpoint.

Instant branches

Full copies in seconds; near-zero extra space.

Time-travel / PITR

Restore to any point in the archived window.

Database per agent

Each AI agent gets an isolated, disposable DB.

Serverless

Idle branches suspend; wake on connect.

High availability

Streaming standby + transparent failover.

One endpoint

Proxy routes by database name to any branch.

1 · Setup

VectoraDB runs inside a Linux VM with ZFS + Docker. On macOS, use Lima:

brew install lima
limactl start --tty=false                     # Ubuntu VM named "default"

Install ZFS, Docker and Go in the VM, and create a ZFS pool on a file-backed device:

lima sudo apt-get update
lima sudo apt-get install -y zfsutils-linux docker.io golang-go
lima sudo truncate -s 30G /var/lib/vectoradb-zpool.img
lima sudo zpool create -f vectoradb /var/lib/vectoradb-zpool.img
lima sudo zfs create vectoradb/branches

Build the image and the CLI inside the VM (the repo is auto-mounted at the same path):

lima bash -c 'cd <repo> && sudo docker build -t vectoradb/postgres-walg:16 docker/postgres \
  && go build -o /tmp/vectoradb ./cmd/vectoradb'

2 · Start

One command brings everything up in the background (no terminal held open):

lima /tmp/vectoradb start

Lima forwards the ports to your Mac:

ServiceURL
Dashboardhttp://localhost:8080
Proxy (SQL)postgres://vectoradb:vectoradb@localhost:6432/<branch>
Agent APIhttp://localhost:8088
Web SQL consolehttp://localhost:8081
Object storagehttp://localhost:9001
lima /tmp/vectoradb status     # what's running
lima /tmp/vectoradb stop       # stop everything
From your Mac the binary lives in the VM, so every command is lima /tmp/vectoradb ….

3 · Branches

A branch is an instant copy-on-write clone of main with its own Postgres. Create them from the CLI or right on the dashboard.

Create, list, delete

lima /tmp/vectoradb branch create qa
lima /tmp/vectoradb branch list
lima /tmp/vectoradb branch delete qa

4 · Connect & CRUD

Connect through the proxy with the branch name as the database. Use the web console or any Postgres client / psql:

lima psql "postgres://vectoradb:vectoradb@127.0.0.1:6432/qa"

Then ordinary SQL — create, read, update, delete:

CREATE TABLE notes (id serial PRIMARY KEY, body text, created_at timestamptz DEFAULT now());
INSERT INTO notes (body) VALUES ('first note'), ('second note');
SELECT * FROM notes;
UPDATE notes SET body = 'edited' WHERE id = 1;
DELETE FROM notes WHERE id = 2;
Writes on qa never touch main or any other branch — full isolation.

5 · Time-travel / PITR

Every change is archived to object storage. Restore to a point in time into a disposable instance (port 5433):

lima /tmp/vectoradb backup create
lima /tmp/vectoradb restore --to latest
lima /tmp/vectoradb restore --to '2026-08-25 12:00:00+00'

6 · Suspend / resume (serverless)

The proxy suspends branches idle beyond --idle (default 2m) and wakes them on the next connection. You can also do it by hand:

lima /tmp/vectoradb branch suspend qa    # stop (data preserved)
lima /tmp/vectoradb branch resume qa     # start again

7 · Agent databases

Give each AI agent its own instant, isolated, disposable database over HTTP:

curl -X POST localhost:8088/agents/alice/branch    # -> { "dsn": "postgres://…/vectoradb", … }
curl localhost:8088/agents                          # list agent databases
curl -X DELETE localhost:8088/agents/alice/branch   # tear it down

The agent connects to the returned dsn like any PostgreSQL and works in full isolation.

8 · High availability

Provision a hot standby that streams from the primary; failover promotes it and the proxy reroutes main transparently, so clients keep the same connection string:

lima /tmp/vectoradb ha enable
lima /tmp/vectoradb ha status
lima /tmp/vectoradb ha failover
lima /tmp/vectoradb ha disable
